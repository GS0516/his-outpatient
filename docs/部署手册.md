# 部署手册（本机没有 Docker 也能交）

> 结论先说：**本机不需要装 Docker，也不需要本地构建镜像**。
> 课程第 9 课要的是「别人在别的电脑打开浏览器能用」+「compose / CI 配置」，这两件事都可以在云端完成。
> 下面四条路线，按你手头的条件选一条即可。

## 路线对照

| 路线 | 需要本机 Docker | 需要账号 | 适用场景 | 工作量 |
|---|---|---|---|---|
| **A. Render 单服务（推荐）** | ❌ | GitHub + Render | 一个 HTTPS 地址同时跑前端和 API，无跨域 | 10 分钟 |
| B. Vercel 前端 + Render API | ❌ | GitHub + Vercel + Render | 课程明确要求"前端 Vercel、后端 Render" | 20 分钟 |
| C. CI 构建镜像 → GHCR → Render 拉镜像 | ❌ | GitHub（+Render） | 想证明"镜像真的能构建"、要交付镜像 | 15 分钟 |
| D. 本机 Docker Desktop | ✅ | 无 | 老师要现场看 `docker compose up` | 30 分钟（装 WSL2 + Docker） |

---

## 路线 A：Render 单服务（最省事，推荐）

单镜像内已经包含「前端构建产物 + FastAPI」：`Dockerfile` 先 `pnpm build`，再把 `dist` 交给 FastAPI 的静态托管，同域访问，**没有 CORS 问题**。

1. 把仓库推到 GitHub：
   ```bash
   git init && git add . && git commit -m "feat: 门诊医生工作站"
   git remote add origin https://github.com/<你>/<仓库>.git
   git push -u origin main
   ```
2. Render 控制台 → **New → Blueprint** → 选仓库（会自动读取根目录 `render.yaml`）。
3. 若不用 Blueprint，也可 **New → Web Service**：Runtime 选 **Docker**，Dockerfile Path 填 `./Dockerfile`，Health Check Path 填 `/api/health`。
4. 环境变量（Blueprint 已带大部分）：
   - `JWT_SECRET`：用 Render 的 Generate 生成（≥32 字节）
   - `ALLOW_ORIGINS`：`https://<你的服务名>.onrender.com`
   - `DATABASE_URL`：`sqlite:////data/his.db`
   - `AI_ENDPOINT` / `AI_KEY`：不填就走本地规则降级
5. 点 Deploy，等构建日志出现 `Uvicorn running on http://0.0.0.0:8000`。
6. 验证：
   ```bash
   curl -s https://<服务名>.onrender.com/api/health
   # {"status":"ok","app":"his","version":"3.0.0","db":true}
   curl -s -X POST https://<服务名>.onrender.com/api/auth/login \
        -H "Content-Type: application/json" \
        -d '{"username":"doctor","password":"Doctor@123"}'
   ```
7. 浏览器打开 `https://<服务名>.onrender.com` → 登录页 → 用 doctor 登录。

> 免费实例会休眠：**答辩前 10 分钟先访问一次预热**，别等上台才第一次打开。

## 路线 B：Vercel 前端 + Render 后端（课程原文的组合）

### B1. 后端（Render）

- New → Web Service → Runtime **Docker**，Dockerfile Path 填 `./server/Dockerfile`（只跑 API，不含前端）。
- 环境变量：
  - `JWT_SECRET`（生成）
  - `DATABASE_URL=sqlite:////data/his.db`
  - `ALLOW_ORIGINS=https://<你的 vercel 域名>`（**必须精确，不能写 \***）
  - `STATIC_DIR`：留空（此镜像里没有前端产物）
- 健康检查 `/api/health`。

### B2. 前端（Vercel）

- Import 仓库 → **Root Directory 选 `web`** → Framework 选 Vite（`vercel.json` 已给出 build/output 配置）。
- 关键一步：环境变量 `VITE_API_BASE=https://<你的 api>.onrender.com`（**构建期变量**，改了要重新部署）。
- 部署完成后，把 Vercel 域名回填到 Render 的 `ALLOW_ORIGINS`，再重新部署一次后端。

> 为什么容易 404：`VITE_API_BASE` 是构建时写进 JS 的，部署后再改环境变量不会生效，必须 Redeploy。

## 路线 C：用 CI 构建镜像（本机不装 Docker 也能"有镜像"）

仓库的 `.github/workflows/ci.yml` 已经包含：

1. `api` 任务：安装依赖 + `pytest`
2. `web` 任务：`pnpm build`
3. `docker` 任务：分别构建 `server/` 与 `web/` 镜像（**验证 Dockerfile 可构建**）
4. `images` 任务（仅 main 分支）：把单镜像推到 GHCR
   `ghcr.io/<owner>/<repo>/his-outpatient:latest`

怎么用它：

- 打开 GitHub → Actions → 最近一次 run，`docker` 任务绿 = 两个 Dockerfile 都能构建；
- `images` 任务绿后，GitHub → Packages 里能看到镜像（默认私有，可在 Package settings 改为 public）；
- Render 也可选 **Deploy an existing image**，填 `ghcr.io/...:latest`（私有镜像需在 Render 配 registry 凭据）。

这样"本机没构建"不是问题：构建发生在 GitHub 的 ubuntu runner 上，日志和产物都可查。

## 路线 D：本机 Docker（只有老师要求现场演示时才需要）

Windows 11：

1. 启用 WSL2：管理员 PowerShell `wsl --install`，重启。
2. 安装 Docker Desktop（含 WSL2 backend），启动后确认 `docker version` 有输出。
3. 在仓库根目录：
   ```bash
   docker build -t his-outpatient .
   docker run --rm -p 8080:8000 -e JWT_SECRET=local-dev-secret-32-bytes-minimum his-outpatient
   # 打开 http://localhost:8080
   ```
4. 或直接 `docker compose up -d --build`（web 8080 + api 8000）。

装不上 Docker 时不要硬扛：用路线 A/B，答辩时展示 Render 的构建日志同样能证明"可部署"。

## 数据持久化（重要）

| 方案 | 数据是否保留 | 说明 |
|---|---|---|
| Render 免费 + SQLite | ❌ 重启/重新部署后重置 | 启动时自动建表 + 灌种子，演示够用 |
| Render Starter + 磁盘 `/data` | ✅ | 取消 `render.yaml` 里 disk 注释 |
| Render PostgreSQL | ✅ | 建 PG 实例，`DATABASE_URL=postgresql+psycopg2://...`，代码已支持 |
| 本机 / 自建 VPS + 卷 | ✅ | compose 的 `his_data` 卷 |

## 常见坑

1. **CORS 报错**：`ALLOW_ORIGINS` 必须与浏览器地址栏的 origin 完全一致（含协议、端口，不带结尾斜杠）。
2. **接口 404**：Vercel 场景下多半是 `VITE_API_BASE` 没配或没重新部署。
3. **登录 401 但密码没错**：后端重建过数据库，种子账号仍在；若改过种子口令，旧库不会自动更新——删库重建。
4. **Render 免费实例打不开**：休眠，预热 10 分钟。
5. **SQLite 只读/无法写**：`/data` 没挂卷或权限不对；用 `sqlite:////data/his.db`（四个斜杠）。
6. **健康检查一直失败**：路径必须是 `/api/health`；容器内端口 8000。
7. **镜像构建时 pnpm 报 `packages field missing`**：`web/pnpm-workspace.yaml` 必须保留 `packages: ["."]`。

- [ ] `https://<域名>/api/health` 返回 `db: true`
- [ ] 浏览器能打开登录页，doctor 登录成功

## 附：Render 要绑卡，不想绑怎么办

Render 免费层也会要求填卡，是**身份验证/防滥用**，正常使用不扣费（可能有一笔 $1 预授权后退回）。
如果不想绑卡，有三条路，按"答辩要不要永久地址"来选：

### 方案 1：Cloudflare 临时隧道（最快，不绑卡，5 分钟）

前提：演示那台电脑要开着。

1. 本机跑单服务（前端 + API 同一个端口）：
   双击 `start-single.bat`，或手动：
   ```bash
   cd web && npm run build && cd ..
   set STATIC_DIR=%cd%\web\dist
   cd server && ..\.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
2. 另开一个窗口安装并启动隧道：
   ```bash
   winget install --id Cloudflare.cloudflared
   cloudflared tunnel --url http://localhost:8000
   ```
3. 它会打印一个 `https://xxxx.trycloudflare.com` 地址，手机热点打开验证一次即可。

优点：不用注册、不用卡、同域无跨域；缺点：电脑关了地址就失效。

### 方案 2：Hugging Face Spaces（免费、不绑卡、有永久地址）

1. 注册 huggingface.co（邮箱即可，不绑卡）→ New → Space → SDK 选 **Docker**。
2. 把仓库推到这个 Space（它就是一个 git 仓库）：
   ```bash
   git remote add hf https://huggingface.co/spaces/<你的用户名>/his-outpatient
   git push hf main
   ```
3. 在 Space 根目录的 `README.md` 顶部加三行 front matter（只影响 HF，不影响 GitHub 那份）：
   ```yaml
   ---
   title: 门诊医生工作站
   sdk: docker
   app_port: 8000
   ---
   ```
4. 等它构建完，地址形如 `https://<用户名>-his-outpatient.hf.space`。

注意：免费 Space 的磁盘是临时的，重启后数据回到种子；演示够用。

### 方案 3：学校/实验室服务器 + 学院域名

有 Linux 机器就最省事：
```bash
git clone https://github.com/GS0516/his-outpatient.git && cd his-outpatient
docker compose up -d --build     # 或 setup.bat 那套手动起
```
再让管理员把 80/443 指过来，或直接用 `http://服务器IP:8080`（课程答辩通常接受）。

### 不建议

- 到处找"免费容器"填别人的卡：账号与数据都不安全。
- 把 `JWT_SECRET` 写死进仓库换取"一键部署"：违反第 7 课安全要求。
